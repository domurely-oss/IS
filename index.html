第1單元｜資通安全基本觀念

詳細版：依教材原章節順序整理，保留法規、流程、數字、比較與實務重點；各小節可展開/收合。
1-1｜資通系統、資通服務與保護標的
  • 資通系統：用以蒐集、控制、傳輸、儲存、流通、刪除資訊，或對資訊進行其他處理、使用或分享之系統。教材例示全球資訊網、eCPA人事服務網、公文系統、差勤系統等。
  • 資通服務：與資訊蒐集、控制、傳輸、儲存、流通、刪除、其他處理、使用或分享相關之服務；教材例示個人電腦維護、伺服器維護。
  • 要保護的對象：資訊/資料、軟體、硬體、網路、人員。這些不只包含設備，也包含人與資訊本身。
  • 資產（asset）：對組織具價值之任何事物。教材以 CNS 27002：2023 說明主要資產可包含資訊、營運過程及活動；支援資產可包含硬體、軟體、網路、人員、場域及組織結構。
教材定位：第1天 1-9～1-11
1-2｜建立資通安全危機意識
  • 資通系統遭攻擊而停擺時，可能對機關造成重大影響；資安危害的影響可能超過一般人的想像。
  • 攻擊面廣且無孔不入。教材以物聯網、行動與無線通訊為例，提醒便利性增加的同時也可能引入新的風險。
  • 資安不是資訊單位單獨的責任，而是每一個人應有的責任與警覺；教材並強調資安與國家安全息息相關。
教材定位：第1天 1-12
1-3｜資通安全與資通安全事件的法定概念
  • 資通安全：防止資通系統或資訊遭受未經授權之存取、使用、控制、洩漏、破壞、竄改、銷毀，或其他情形影響其機密性、完整性或可用性。
  • 資通安全事件：系統、服務或網路狀態經鑑別而顯示可能有違反資通安全或保護措施失效之狀態發生，並影響資通系統機能運作。
  • 教材事件例子：個資電子檔外洩、系統資料遭勒索病毒加密破壞、系統當機無法正常提供服務。
教材定位：第1天 1-13

第3單元｜資通安全風險管理

詳細版：依教材原章節順序整理，保留法規、流程、數字、比較與實務重點；各小節可展開/收合。
3-1｜風險的定義與風險管理目標
  • 風險：威脅利用其相對應脆弱性，造成組織/機關資訊資產受到衝擊的可能性。
  • 風險影響程度由「衝擊」與「可能性」兩個因素結合而定。
  • 風險管理的目標不是追求最強固防護，而是在最低防護成本投入下獲得最適合的安全性。
教材定位：第1天 1-62
3-1｜衝擊準則
  • 衝擊準則主要衡量威脅與弱點結合後，破壞資訊/系統的機密性、完整性、可用性，對組織造成的嚴重性。
  • 衝擊可包含營運受損、信譽損害、資安危害、業務與財務價值損失及違法情形。
  • 教材建議將衝擊嚴重性分為普、中、高3等級，並依CIA被破壞程度說明其對組織的影響。
教材定位：第1天 1-63
3-2｜風險管理全景建立
  • 機關應先界定風險評鑑範圍、角色及責任，再執行風險評鑑及控制措施。
  • 外部環境：社會文化、政治、法律、法規命令、財務、科技、經濟、自然環境與競爭環境等。
  • 內部環境：治理、組織架構、角色責任、政策、目標、策略、能力、資源與知識。
  • 應規劃風險管理作法、風險評估準則、衝擊準則與風險接受準則；詳細風險評鑑時還要清查盤點範圍內所有資產並整合跨部門成員。
教材定位：第1天 1-65～1-66

8-1｜資訊委外的法規要求
  • 資通安全管理法第10條：委外建置、維運或提供資通服務時，應選任適當受託者，要求建立有效資安管理機制並監督實施。
  • 施行細則第9條第1項第11款：資通安全維護計畫應包含資通系統或服務委外之管理措施。
  • 責任等級分級辦法第11條第2項：自行或委外開發之資通系統都要依附表九完成分級並依附表十執行控制措施。

項次重點

5受託者違反資安法令或知悉資安事件時，立即通知委託機關並採補救措施
6委託關係終止/解除時，確認資料返還、移交、刪除或銷毀

8委託機關定期或知悉可能影響受託業務之事件時，以稽核或其他適當方式確認執行情形

iPhone / iPad 開啟方式

本版本仍是單一 HTML，不需要安裝 App、Python 或其他套件，並會自動偵測 iPhone / iPad。

1將 HTML 檔儲存到 iPhone / iPad 的「檔案」App。
2點選 HTML 開啟；若只顯示預覽，請用分享選單改以可執行網頁的瀏覽器開啟。
3若放在內部網站 / Web Server，Safari 可使用「加入主畫面」，以接近 App 的全螢幕模式開啟。
4iPhone 採單欄＋底部導覽；iPad 會依直向 / 橫向自動調整雙欄空間。
不同 iOS / iPadOS 版本對本機 HTML 的預覽方式可能不同；若互動功能在檔案預覽器中受限，改用 Safari / Edge 或內部 Web Server 會較穩定。
